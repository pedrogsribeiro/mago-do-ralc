# Estudo 19: Maravilhas, Fetiches, Talismãs e Dispositivos

Este estudo trata Maravilhas como **família de itens com funções mecânicas diferentes**, não como um subsistema único.

A bíblia distingue:

1. **Bugigangas (Trinkets)** — passivas;
2. **Amuletos/Matrizes** — reservas de Quintessência;
3. **Fetiches** — objetos com espírito aprisionado;
4. **Talismãs/Dispositivos** — itens com Arete/Iluminação próprios.

A pergunta correta é:

> **qual parte do item já é naturalmente player-facing e qual operação, se alguma, ainda pertence ao ST?**

---

## 1. Gate de fidelidade

A experiência do jogador precisa preservar:

* Paradigma/compatibilidade;
* Arete/Iluminação próprio do item;
* Gnose do espírito no Fetiche;
* Força de Vontade do usuário;
* Quintessência;
* Primórdio;
* custos de criação;
* Paradoxo;
* testes estendidos de fabricação;
* diferenças entre categorias.

A camada player-facing não deve:

* transformar toda Maravilha em “item com cargas”;
* substituir Arete do item pelo Arete do usuário;
* apagar Gnose do Fetiche;
* ignorar Paradigma;
* remover Paradoxo;
* converter criação em teste simples.

---

## 2. Bugigangas

Bugigangas são passivas.

Elas não possuem:

* Arete;
* Quintessência própria;
* ativação complexa.

### Gate

**PASSAM SEM CONVERSÃO.**

A interface só precisa registrar o efeito passivo relevante.

---

## 3. Amuletos e Matrizes

Amuletos/Matrizes são reservas de Quintessência.

A bíblia determina:

* capacidade de até 5 Quintessências por nível de Maravilha;
* exige Primórdio 2 para extração/recarga;
* exige pelo menos 1 turno de concentração.

Isso já é naturalmente player-facing.

### Gate

**PRESERVAR COMO RECURSO.**

Não há razão para convertê-los em Relógio genérico.

---

## 4. Talismãs e Dispositivos

Talismãs/Dispositivos possuem **Arete/Iluminação próprios**.

Quando o PJ ativa o item:

> **o jogador rola o Arete/Iluminação do item.**

Isso já satisfaz a arquitetura player-facing.

A ficha do item deve preservar:

* Arete/Iluminação;
* Esferas/poderes;
* Quintessência, se houver;
* Paradoxo;
* requisitos/compatibilidade.

### Gate

**PASSA SEM CONVERSÃO.**

---

## 5. Fetiches

A ativação do Fetiche já é centrada no jogador:

```
usuário rola Força de Vontade D7
contra Gnose do espírito
```

Se obtém sucesso:

> a própria **Gnose do espírito** é usada como parada para manifestar o poder.

Aqui existem duas etapas.

### 5.1. Ativação

A oposição da Gnose do espírito pode ser tratada pela família de **Oposição resistida**, desde que a regra original de cancelamento esteja clara no procedimento.

A rolagem do jogador permanece Força de Vontade D7.

### 5.2. Manifestação do poder

A Gnose passa a ser a parada do poder.

Se a manifestação já é rolada pelo jogador como operação do Fetiche, preserva-se.

Se o procedimento específico exigir rolagem do ST, aplica-se a regra de fidelidade dos Estudos 00/14.

### Gate

**PASSA COM DISTINÇÃO ENTRE ATIVAÇÃO E EFEITO.**

---

## 6. Paradigma e compatibilidade

A Maravilha não é apenas estatística.

A bíblia determina compatibilidade paradigmática:

* personagem pode não conseguir usar tecnologia que rejeita;
* personagem pode não conseguir usar bruxaria que rejeita.

Isso é uma **condição de uso**, não uma dificuldade genérica.

### Gate

**PRESERVAR COMO REGRA FICCIONAL/MECÂNICA.**

---

## 7. Paradoxo

O Paradoxo gerado pela ativação vai para o **mago usuário**, não para o item.

Isso deve permanecer explícito.

A ativação de Maravilhas não cria um subsistema paralelo de Paradoxo.

### Gate

**PRESERVAR O SUBSISTEMA GERAL.**

---

## 8. Criação de Maravilhas

A criação já é estruturada como processo estendido:

* requisitos de Esferas;
* Habilidades mundanas;
* testes estendidos;
* investimento de Quintessência;
* Quintessência adicional por tentativa;
* custo opcional para elevar Arete.

Isso pode usar Relógio apenas como interface visual do número de sucessos/tentativas, sem alterar a lógica.

### Gate

**PASSA COMO TESTE ESTENDIDO.**

---

## 9. Maravilha autônoma

Um item só deve ser tratado como agente quando ele realmente possuir:

* autonomia;
* ações próprias;
* intenção/programação operacional;
* capacidade de iniciar efeitos independentemente do usuário.

Nesse caso:

* pode ser constructo-agente;
* pode possuir Ameaça/Oposição;
* pode agir em iniciativa.

Um Talismã passivo ou arma mística comum não vira NPC apenas por ser mágico.

---

## 10. Matriz operacional

| Categoria | Tratamento |
| :--- | :--- |
| Bugiganga | efeito passivo |
| Amuleto/Matriz | reserva de Quintessência |
| Talismã/Dispositivo usado por PJ | jogador rola Arete/Iluminação do item |
| Fetiche — ativação | FV do jogador vs Gnose |
| Fetiche — poder | Gnose conforme procedimento específico |
| Criação | teste estendido + custos |
| Paradoxo | recai no usuário |
| Compatibilidade | condição paradigmática |
| Maravilha autônoma | constructo-agente se realmente houver agência |

---

## 11. Exemplo estrutural

```
DISPOSITIVO TECNOCRÁTICO

Tipo:
Talismã/Dispositivo

Arete/Iluminação:
4

Poderes:
Forças 3
Correspondência 2

Quintessência:
reserva própria, se aplicável

Uso:
jogador rola Arete/Iluminação 4

Paradoxo:
vai para o usuário

Compatibilidade:
exige paradigma compatível
```

Nenhuma nova mecânica player-facing é necessária.
